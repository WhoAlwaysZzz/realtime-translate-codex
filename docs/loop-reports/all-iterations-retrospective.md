# Agent Loop 全轮次回顾

生成日期：2026-09-01。范围：根据 `docs/agentic-loop.log` 的两组轮次计数（旧回放 61 轮、后续质量循环 39 轮）及 Git 历史重建，共 100 个可识别编号。日志存在重复追加、网络中断和部分乱码；因此“改动”以提交为直接证据，“结果”仅在日志/报告明确时陈述，其余标注为推断或证据不足。由于提交没有保存统一的 iteration-id，以下逐轮与提交的对应是阶段性近似，不能当作原始审计记录；本文不把通过测试等同于产品完成。

## 统计

- 可识别轮次：100（日志计数层面：旧回放阶段 1-61；后续 OCR/卡片质量阶段 1-39，本文为便于阅读连续编号为 62-100）。
- 有较完整输出或对应提交证据：约 39 轮（后期质量循环及少数回放轮）。
- 主要依赖心跳、提交时间或阶段映射：约 61 轮；其中许多只有“进程退出 0”，无法可靠还原语义结果。
- 历史限制：同一日志被多次追加，早期 runner 重复记录 iteration=1；因此不存在逐轮完整、无歧义的原始报告。

## 结论与未决问题

历史工作确实覆盖了从查词 overlay、OCR/回放基础设施到上下文排序、卡片层级和学习证据的演进。但 100 轮中只有后期少数轮次有可审计的前后样例；旧回放阶段大量轮次只能证明“运行过”，不能证明“识别正确”。最关键的未决问题仍是上下文 OCR 的字符/词级真值，以及卡片学习内容是否帮助记忆。后续应以逐轮报告和独立评委为准，不再用心跳或非空 OCR 作为成功标准。
