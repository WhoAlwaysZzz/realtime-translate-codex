# Agentic Loop: 唯一目标——提升卡片内容质量

不要重复验证已经基本完成的 OCR、截图回放、托盘、热键或基础查词功能。除非它们直接阻碍卡片内容，否则本循环不得把工作量花在这些指标上。

## 产品问题

用户框选一个游戏中的英文词后，当前卡片常常像词典复制品：信息太多、当前句义不突出、解释不自然，或者虽然“有结果”却不能帮助用户马上理解剧情。目标是让用户在很短时间内知道：这个词在这句话里是什么意思、为什么是这个意思、是否仍然不确定。

## 必须尝试的方向

每轮只能选择一个最高价值内容问题，并实际修改代码或内容架构；不能只写分析报告。

1. **卡片结构重做**：核心内容优先于词频、词族、构词等学习附加信息。设计并实现适合游戏阅读的固定层级：当前句义、短解释、词性、证据/上下文、少量候选义项。
2. **翻译来源对比**：比较本地词典、规则语境排序、短语/搭配库、可选 AI 解释等方案。可以改变现有架构；不得因为已经有本地词典就默认继续堆词典字段。
3. **语境解释**：让系统解释词在当前句子中的功能，而不是只返回中文同义词。优先支持短语、固定搭配、习语、角色称谓和游戏专有表达。
4. **不确定性表达**：当证据不足时，卡片应明确显示“可能是……，但无法仅凭这一句确定”，而不是把多个释义挤在一起或强行选择。
5. **速度与降级**：探索本地即时首卡 + 可选异步增强卡；AI 只能作为增强，不得让用户等待才能看到基础理解。比较实际延迟、价格和质量收益。
6. **内容质量评审**：使用真实游戏截图和人工判断，逐张检查“看完卡片是否能继续读懂这句话”。测试不是目的，必须能证明卡片内容发生了改善。

## 质量验收标准

- 至少建立 20 条真实游戏语境样本，每条记录当前句、目标词、人工认可的解释和不可接受的解释。
- 对每条样本，卡片首屏必须在最醒目的位置给出一句自然、简洁的“本句意思”；不得让用户从长串词典字段中自行推断。
- 人工盲评中，至少 16/20 条样本能让熟悉产品的用户直接判断当前句义；至少 4 条歧义样本明确弃答或标注不确定，不得伪装成确定答案。
- 卡片首屏最多保留 5 个信息块；词频、词族、构词只能作为折叠或次要信息。
- 本地基础卡片不等待网络；增强解释失败时，基础卡片仍完整可读。
- 每次架构或提示词改变，都必须保留前后卡片样例，说明质量到底改善、退化还是没有变化。

## 循环停止条件

循环有三种终止状态，而不是无限运行：

1. **等待人工评审**：如果下一步只能由用户或独立评审者判断，agent 创建 `docs/agent-loop.waiting-for-review.md`，写明评审文件和恢复方式；runner 必须退出，不能空转。
2. **真实阻塞**：缺失外部权限、服务或输入且无法安全替代时，更新状态为 blocked 并退出；不得把同一个失败反复重试。
3. **等待用户验收**：只有上述内容质量标准有真实样例和前后对比证据，并且用户实际看过卡片后明确验收，才可视为完成。

循环不得自行创建或修改 `docs/agent-loop.accepted`。
