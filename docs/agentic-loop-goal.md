# Agentic Loop: 产品完成定义（面向真实游戏阅读）

## 用户要解决的具体问题

用户在英文游戏剧情中遇到少量不懂的词，希望用鼠标框选后，在几秒内得到足够准确、简洁、能结合当前句子的中文解释，然后立即继续阅读。产品不是整句自动翻译器，也不是词典数据展示器；它必须减少打断感，同时支持把查过的词留下来复习。

## 完成门槛（全部满足后才可请求用户验收）

### A. 真实使用链路（权重 25%）

- Release 程序可启动、托盘可用，右键框选在游戏窗口上工作；不得要求用户切换到测试窗口。
- 从真实归档截图回放至少 30 条游戏剧情样本：OCR 非空率 ≥95%，正确词命中率 ≥90%，端到端失败和超时各 ≤5%。
- 对不可读截图、非游戏截图、空选区给出明确可操作提示，不弹出伪造释义。

### B. 卡片内容（权重 30%）

每张普通单词卡必须按固定顺序显示：

1. 原词及归一化词形；
2. 当前句中最可能的中文含义（只有证据足够时才标为“当前句义”）；
3. 词性；
4. 一句非常短的中文语境解释；
5. 必要时列出最多 2 个候选义项，并说明“无法确定”；
6. 一个简短英文原句片段或上下文提示；
7. 可选的词族/词形信息，不得挤占核心释义。

- 禁止把整段词典原文直接倾倒给用户。
- 对真实标注集，当前句首选义准确率 ≥90%；歧义样本的诚实弃答率 ≥80%；不得为了提高命中率而强行猜测。
- 首屏核心内容在普通本地查词场景下 ≤1 秒出现。

### C. 速度、价格和降级（权重 15%）

- 普通单词查词默认完全本地、无 API 费用；P50 ≤1 秒，P95 ≤2 秒（从松开鼠标到卡片出现）。
- AI 只用于本地证据不足或用户主动请求的语境解释，不得阻塞普通查词。
- AI 请求必须有超时、取消、错误提示和本地基础结果；记录 provider、model、耗时和错误，但不记录 API 密钥。
- 用脱敏的固定句集测量至少 20 次请求，记录 P50/P95 延迟和每千次请求估算成本；在文档中明确可接受上限（目标：P95 ≤5 秒，单次成本 ≤人民币 0.02 元）。

### D. 学习记录和隐私（权重 10%）

- 查词历史可按时间查看、复制和再次打开；同一词重复出现时保留最近语境。
- 截图保存开关真正生效；关闭后 OCR 仍可用且不写入 PNG。
- 回放/测试记录与用户正式历史隔离；所有本地记录路径和可删除方式写入 README。

### E. 可验证性和工程质量（权重 20%）

- 每个产品门槛都有可重复的命令或脚本、输入集、输出证据和日期。
- 必须同时有单元测试、真实截图回放和至少一次可见桌面验证；不能用单元测试代替用户体验验证。
- 每轮循环只解决一个最高价值阻塞点，构建必须 0 警告/0 错误，提交保持聚焦。
- 状态报告必须列出：已完成指标、未完成指标、证据文件、下一步，以及“尚未达到完成”的原因。

## 循环执行顺序

1. 先审查当前卡片和真实截图，补齐 30 条带人工语境真值的游戏样本（含至少 5 条应弃答歧义样本）。
2. 重新设计并实现卡片数据结构、排序、弃答和 UI 展示，优先解决“几秒内看懂”。
3. 为本地快速结果与可选 AI 深度解释建立非阻塞两级流程，并测量真实延迟/成本。
4. 验证历史、截图开关、隐私隔离和桌面行为。
5. 只有所有门槛有证据后，停止修改并等待用户实际验收。

循环不得自行创建或修改 `docs/agent-loop.accepted`；该文件只能由用户明确验收后创建。
