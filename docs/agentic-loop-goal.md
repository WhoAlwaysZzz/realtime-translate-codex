# Agentic Loop: 通用 OCR 基础 + 游戏对白增强 + 单词学习

## 产品边界

工具的基础操作必须保持通用：用户可以在游戏、浏览器、视频、聊天窗口等任意可见英文区域框选文字。针对《重返未来：1999》剧情对白的优化是当前最高优先级，但必须作为可识别、可关闭的增强层，不能把固定屏幕坐标或固定裁剪范围写死为唯一 OCR 模式。

## 目标

1. 可靠恢复目标词所在的游戏对白行，错误上下文不得驱动释义；
2. 首屏帮助用户立即理解当前句；
3. 学习层帮助用户理解并记住单词本身，而不是重复一次性中文答案。

## OCR 与上下文指标

建立至少 50 条真实游戏截图金标准语料；两个独立 agent 盲转写一致才计入，分歧标为 `uncertain`。目标：目标对白行恢复率 ≥95%，上下文 WER ≤8% 或关键内容词准确率 ≥92%，可信度门控 precision ≥95%、recall ≥85%，低质量上下文强行影响主释义为 0。通用桌面样本必须保持可用，不能因游戏增强层退化。

必须比较多 OCR 引擎或预处理方案，而不是默认当前 Windows OCR 足够。保留行、词、坐标和质量信息；执行多版本竞争；用选区锚点选择附近对白行；必要时让游戏对白增强层只在检测到相应布局时启用。通用模式仍使用自适应选择，不能依赖固定坐标。低可信结果必须安全降级。

## 学习型卡片

首屏最多五块：原词/词形、当前句义、词性、短语功能、上下文可信状态。学习层只展示有来源的 1–2 项：核心概念、常见搭配、可信词形/构词线索或能区分多义词的例子。每项必须有来源和置信度；没有可靠证据就省略，不生成空泛记忆故事。

至少 30 个真实游戏词进行学习评估：独立评委判断首屏可继续阅读 ≥90%，学习层真正帮助理解单词本身 ≥80%，事实或来源错误为 0，空泛/重复信息 ≤10%。

## 循环报告与评审

每一轮必须生成 `docs/loop-reports/iteration-<n>.md`，包括：本轮假设、改动文件和 commit、前后样例、量化结果、失败/退化、独立评委决定、下一轮问题。即使没有代码变更，也必须报告“为什么没有变更”，不能只在总日志里留下不可读的原始输出。

涉及 OCR、上下文、卡片或学习内容的提交，必须启动独立只读评委。评委要看真实截图、金标准、前后卡片和来源，明确挑剔地输出 `accept`、`reject` 或 `insufficient-evidence`；实现 agent 不得自评成功。

达到指标并连续两批获得两个独立评委 `accept` 后自动停止，生成自动验收报告；否则继续推进最高价值问题。不得删除用户文件、截图或历史记录。
